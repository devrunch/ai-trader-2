# AI Trader 2 — Delivery Roadmap

**Spec:** `docs/SRD.md` · **Benchmarks:** `docs/benchmarks/` · **Process:** `docs/process/WORKFLOW.md` (written in Phase 0, Task 1)

The phases run in order. Each phase gets its own detailed plan, written when that phase starts, so it uses what the earlier phases actually built rather than guesses. Only Phase 0 is planned in detail now: `2026-11-08-phase-0-foundation.md`.

## How every phase is delivered (manager → employee)

- **Claude is the manager.** It writes the phase plan and each task brief, reviews every diff against `AGENTS.md` and the cited SRD requirements, owns the architecture diagrams, and is the only one who merges to `main`.
- **Codex is the employee.** It implements one small task at a time on its own branch `task/<id>-<slug>`.
  - **What blocks a direct commit:** Codex's sandbox can't write `.git`; verified 2026-11-08 with `codex-cli 0.163.0`, even with `--add-dir .git`.
  - **Who commits:** the manager commits the reviewed work on the task branch with `--author "Codex <codex@users.noreply.local>"`.
- **Nothing reaches `main`** until `pnpm check` passes on the branch, the review checklist is green, and the feature's diagrams are updated. Merges use `--no-ff`, so every task stays one visible unit in history.
- **Every feature updates the architecture model** under `architecture/`:
  - the LikeC4 model;
  - the feature's sequence and state diagrams;
  - regenerated class and dependency diagrams;
  - dead-code (knip) and duplication (jscpd) reports.

  A task that leaves the generated diagrams stale fails `pnpm diagrams:check`.

### Why this state setup (live trading UI)

- **Server data (REST)** goes through **TanStack Query**: caching, stale-while-revalidate, prefetch, cancellation on symbol switch (E15). That meets NFR-PF-1/4.
- **UI state** goes in **Zustand**: layout, panels, selected tool, theme. It is small, works with selectors and the React Compiler, and can be read outside React.
- **Live ticks never pass through React state.** At 1–50 ticks per second across a watchlist, re-rendering a component tree per tick is the main cause of janky trading UIs.
  - A plain TypeScript `LiveStore` (one entry per instrument, holding the forming bar and its sequence number) is fed by the socket.
  - The chart adapter subscribes to it imperatively and calls `series.update()`, so the chart never re-renders through React.
  - Text that must show live values (price header, watchlist rows, P&L) reads through `useSyncExternalStore`, with notifications coalesced to at most one per animation frame per key.
- **Ruled out:**
  - Legend-State: v3 still in beta; v2 is older.
  - Jotai: fine, but atoms per tick give no gain over the `LiveStore`.
  - Redux Toolkit and MobX: heavier than this needs.
  - Signals for React: they fight the React Compiler's model.

## Diagrams: what lives where

```
architecture/
  model/                 LikeC4 DSL (*.c4). One file per bounded context, extended feature by feature.
                         `pnpm diagrams:serve` opens the interactive viewer; `pnpm diagrams:build` builds a static site.
  features/<feature>/    README.md: purpose, SRD IDs, Mermaid sequence and state diagrams (hand-written, updated each task).
                         classes.mmd: generated by scripts/diagrams/gen-class-diagrams.ts (ts-morph); never hand-edited.
  generated/             dependency graph (dependency-cruiser, interactive HTML + Mermaid), knip report (dead code),
                         jscpd report (duplication: candidates for shared utils). Rebuilt by `pnpm diagrams`.
```

`pnpm diagrams:check` regenerates every generated file and fails if the git tree changes, so the diagrams can't go stale.
