- `domain/bar-builder.ts`, `bar-builder.spec.ts`: one-minute bars, sequence deduplication, event-time OHLC, cumulative-volume allocation, late corrections, closeDue and restore.
- `domain/repair.ts`, `repair.spec.ts`: sorted union, vendor replacement on OHLC/volume differences and idempotent repeated repair.
- `domain/index.ts`, `index.spec.ts`: public domain exports and API smoke test.
- `apps/api/src/shared/vendors/kite/kite-session.service.ts`, corresponding spec: optional logger injection with a silent unit-test logger; production logging retained.
- `apps/api/test/kite-session.int-spec.ts`: silent logger for the durable-session integration test.
- `apps/api/package.json`, `pnpm-lock.yaml`: the two exact authorized date dependencies.
- `architecture/features/market-data/README.md`: grid/calendar tables, coverage metadata, bar-builder state diagram and repair rules.
- `architecture/features/market-data/classes.mmd`, `architecture/generated/deps.mmd`, `architecture/generated/jscpd.md`, `architecture/model/generated.c4`: generated by `pnpm diagrams`; no hand-authored LikeC4 model changes.

Late tolerance is inclusive and measured against the latest supplied tick or
closeDue time. Event-time sorting keeps open/close and cumulative shares correct
when ticks arrive out of order. Corrections return affected intervening closed
bars as well as the targeted bar. The first cumulative tick establishes the
baseline; restore uses the supplied baseline immediately. Missing cumulative
data leaves that bar's volume null. Cumulative baselines reset on a new
exchange-local trading date. Returned bars are defensive snapshots, and empty
minutes are never fabricated.

## Deviations from the brief, and why

- Per the manager ruling, no unpublished 2027 holiday dates are fabricated.
  NSE, BSE, NFO and MCX return normal weekday sessions after their curated
  coverage boundary, and `holidaysKnownThrough` returns `2026-12-31`.
  Rule-based US and FX calendars return `9999-12-31`.
- Domain errors are plain coded errors and date imports follow the updated
  AGENTS.md. No shared errors or framework dependencies enter the domain.
- Calendar types live in a small `calendars/types.ts` file and are re-exported
  from `calendar.ts` to keep the requested public interface without type cycles.
- Helper holiday data/rule specs in the first partial turn followed their helper
  implementations; the required brief tests were written and observed red first.
- MCX session close times and the Muhurat window follow the explicit task rules.
  The election circular itself quotes an evening close of 23:55 in January;
  the task's DST rule gives 23:30 instead. No additional vendor/session behavior
  was inferred from that source.
