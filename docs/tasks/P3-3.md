## Goal
One browser-side client keeps every chart and price live through drops, sleep, hidden tabs and offline periods, with no reload. Bars stay exactly right: no gaps, no duplicates, and the server always wins.

## Increments

### 1. `SeriesSync`: pure, no socket
```ts
class SeriesSync {
  constructor(opts: { onReset(bars: Bar[]): void; onUpdate(bar: Bar): void })
  applySnapshot(bars: Bar[], seq: number): void   // replaces all state, then onReset
  applyBar(seq: number, bar: Bar): 'applied' | 'stale' | 'gap'
  lastSeq(): number
  lastBarTime(): number | undefined
  mergeHistory(bars: Bar[]): void                  // idempotent by bar.time; the server's values win
}
```
- `seq <= lastSeq` gives `'stale'` (dropped).
- `seq > lastSeq + 1` gives `'gap'` (not applied).
- Otherwise the bar is upserted by `time`, giving `'applied'`.
- A bar whose `time` is older than the newest bar is still upserted (a late correction), never appended out of order.

Tests:
- `duplicate and old seq are dropped`;
- `a seq gap is reported and not applied`;
- `late correction updates the right bar`;
- `mergeHistory is idempotent and server wins`;
- `a tick exactly on the bar boundary lands in the bar the server stamped`.

### 2. `ServerClock`
- `sync(now: () => Promise<number>)` measures the round trip and stores `offset = serverNow - (t0 + rtt / 2)`.
- It keeps the median of the last 5 samples, takes a sample on every connect, and then one every 10 min.
- `now()` returns `Date.now() + offset`.
- The client never decides bar boundaries. The clock is only for display (for example "updated 3 s ago") and for staleness timers.

Test: `offset uses the median and ignores an outlier`.

### 3. `LiveClient`, the connection
- Uses `socket.io-client` (the latest 4.x, an exact pin), `withCredentials`.
- Turns off socket.io's own reconnection. Reconnect ourselves with `backoff` (base 500 ms, max 15 s, full jitter), so every path is testable with fake timers.
- **State**, written to `connection-store.ts` as a Zustand store (`useConnection()`):
  - `connecting`, `live`, `reconnecting { attempt, nextAt }`, `offline` (`navigator.onLine` is false), `unauthorized` (`connect_error` UNAUTHORIZED or `session_expired`; no retry loop: redirect to login is the UI's job).
- **API:**
  ```ts
  subscribe(symbol: string, interval: Interval, handlers: { onReset(bars: Bar[]): void; onUpdate(bar: Bar): void; onStatus(s: DataStatus): void }): () => void
  ```
  - Many callers can subscribe to the same symbol and interval; they share one server subscription (reference counted, released on last unsubscribe).
  - The newest bar's close is also written to `LiveStore` key `price:<instrumentId>`, so `useLiveValue` shows prices without React state.
- **Resync triggers**, each one resubscribing with `afterSeq = sync.lastSeq()`; the server answers with a replay or a fresh snapshot:
  - a reconnect;
  - a `resync` event;
  - `applyBar` answering `'gap'`;
  - `visibilitychange` to visible after being hidden for 5 s or more;
  - the `online` event;
  - waking from sleep, detected as a 15 s timer firing 30 s or more late.

  Collapse triggers that fire together into one resubscribe per subscription.
- **Stale guard:** when `live` but no `bar` and no `status` has arrived for 90 s on a subscription whose status is `ok`, resubscribe it once.
- **History gap after a snapshot:** if the snapshot's oldest bar is newer than the oldest bar the chart already has, the chart's history stays. `mergeHistory` keeps both, so no hole appears.
