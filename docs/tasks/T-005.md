# Task T-005: API config

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal
One typed, validated config object for the API. `process.env` is read in exactly one place (`main.ts`). Bad config fails startup once, listing every problem, without echoing secrets.

## SRD
§10.1 (`shared/config` is the only reader of env), NFR-SC-1 (no secrets leaked), R-9.

## Files
- Create: `apps/api/src/shared/config/app-config.ts`, `apps/api/src/shared/config/load-config.ts`, `apps/api/src/shared/config/config.module.ts`, `apps/api/src/shared/config/index.ts`, `apps/api/.env.example`
- Modify: `apps/api/src/main.ts`, `apps/api/src/app.module.ts`, `apps/api/src/app.module.spec.ts` (pass a test config)
- Test: `apps/api/src/shared/config/load-config.spec.ts`, `apps/api/src/shared/config/config.module.spec.ts`

## Interfaces
- **Produces:**
  - **`AppConfigSchema`** (Zod 4, exact latest 4.x), and `type AppConfig = z.infer<typeof AppConfigSchema>` with these keys:
    - `NODE_ENV`: `'development' | 'test' | 'production'` (required);
    - `PORT`: integer 1–65535, default `8000` (parsed from a string);
    - `DATABASE_URL`: URL with protocol `postgres:` or `postgresql:` (required);
    - `REDIS_URL`: URL with protocol `redis:` or `rediss:` (required);
    - `LOG_LEVEL`: `'fatal' | 'error' | 'warn' | 'info' | 'debug' | 'trace' | 'silent'`, default `'info'`;
    - `CORS_ORIGINS`: comma-separated list of http(s) origins, parsed to `string[]` (trimmed, empty entries dropped), default `[]`.
  - **`class ConfigError extends Error`:** `readonly issues: ReadonlyArray<{ key: string; problem: string }>`. Its `message` is `"Invalid configuration: KEY1 (problem), KEY2 (problem)"`.
  - **`loadConfig(env: Readonly<Record<string, string | undefined>>): AppConfig`:** collects all issues and throws one `ConfigError`. Unknown env keys are ignored. The result object is frozen.
  - **`APP_CONFIG`:** a DI token (a `Symbol`).
  - **`AppConfigModule.forRoot(config: AppConfig): DynamicModule`:** global; provides `APP_CONFIG` with the given value.
  - **`AppModule.forRoot(config: AppConfig): DynamicModule`:** imports `AppConfigModule.forRoot(config)`. Keep a plain `AppModule` class as the module's identity.
  - **`main.ts`:** `loadConfig(process.env)`. On `ConfigError`, write the message to stderr (the `main.ts`-only console allowance) and exit with code 1. Listen on `config.PORT`.

## Tests to write first
**`load-config.spec.ts`:**
- `parses a valid environment` → `PORT` is the number `9000` from `'9000'`; `CORS_ORIGINS` from `'https://a.com, https://b.com,'` is `['https://a.com','https://b.com']`.
- `applies defaults` → with only the required keys, `PORT === 8000`, `LOG_LEVEL === 'info'`, `CORS_ORIGINS` deep-equals `[]`.
- `reports all invalid keys at once` → missing `DATABASE_URL` plus `PORT='abc'` plus `NODE_ENV='prod'` gives a `ConfigError` with `issues.map(i => i.key).sort()` deep-equal to `['DATABASE_URL','NODE_ENV','PORT']`.
- `never echoes secret values in errors` → `DATABASE_URL='mysql://u:s3cr3t@h/db'` (wrong protocol) gives a message and issues that don't contain `s3cr3t`.
- `rejects non-http CORS origins` → `CORS_ORIGINS='ftp://x'` gives an issue keyed `CORS_ORIGINS`.
- `returns a frozen object` → `Object.isFrozen(result) === true`.

**`config.module.spec.ts`:**
- `provides APP_CONFIG globally` → a module that imports `AppConfigModule.forRoot(cfg)` resolves `APP_CONFIG` to the same object.

**`app.module.spec.ts`:** keep `boots the Nest application`, now with `AppModule.forRoot(testConfig)`.
