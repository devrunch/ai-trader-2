## Tests
- `native-runtime.parity.spec.ts`: 47 new variants (115 in all) against PineTS 0.13.1, 1e-9 relative to `max(1, |value|)`, `null` on the same bars. Options per case, documented in the file:
  - `tolerance 1e-7` for `tsi` and `1e-6` for `hv`: PineTS rounds every `ta.*` output to 10 decimals, which these two amplify (a ratio of EMAs of small moves; ×1,900).
  - `earlyStart` for `stochrsi` and `bbw`: PineTS's `ta.stoch`/`ta.highest` skip `na` inside a window and start early. Only "native `null`, PineTS value" is allowed; every bar where both have a value must still match. TradingView, and the native kernel, wait for a full window (the start bars are asserted in `second-batch.spec.ts`).
  - `tradedBars` for `eom`: PineTS's running SMA never recovers from a division by zero, so the fixture's zero-volume bar is given volume 1. The zero-volume behaviour is a hand-checked case.
- `second-batch.spec.ts` (new): 22 hand-checked cases (start bars, TSI → 100 on a rise, UO weights, CMO 100/0/null, AO, DPO plain and centred, PPO, Coppock/KST start bars, BoP, A/D, PVT, Chaikin, EOM with a zero-volume bar, EFI, HV daily vs weekly, %B and BBW, Envelope, LSMA with offset, ALMA, SMMA, McGinley, Volume Oscillator).
- `native-runtime.spec.ts` (loops over the catalog): the forming-bar-ticks-equal-a-fresh-run check now covers all 53.
- `catalog.spec.ts`: ids, defaults/titles/levels, warm-up rules, DPO's plot offset. `indicator.service.spec.ts`: catalog size 53.
- Gate (run once): `pnpm build:packages && pnpm lint && pnpm typecheck && pnpm test && pnpm depcruise && pnpm knip && pnpm jscpd && pnpm build`. All exit 0 (1,260 tests passed, 1 skipped). Lint also needed two fixes in P4-13a files (`pivots.ts` unnecessary cast, `catalog.spec.ts` unbound method).

## Judgment calls
- **Pine sources use `x - x[1]` where TradingView's scripts use `ta.change(x)`** (TSI, CMO, PVT, EOM, EFI): identical values, but PineTS rounds `ta.change` to 10 decimals and the parity would otherwise differ by that rounding.
- **`stochrsi` and `bbw` follow the strict window rule** (see `earlyStart`), the same rule the existing SMA/`stoch` kernels follow.
- **ALMA is not floored** (`ta.alma`'s `floor` defaults to false); PineTS agrees.
- **DPO Period input is titled "Period"; centred DPO paints `−(⌊n/2⌋+1)` bars back** through `plotOffsets`, so the newest bars are empty.
- **Inputs from memory of TradingView's scripts** (I could not open them): Envelope has no Offset input; SMMA, McGinley, HV, A/D, PVT, BoP, AO have none; Volume Oscillator's plot is titled "OSC"; zero lines on TSI, CMO, AO, DPO, PPO, Coppock, KST, BoP, Chaikin, EOM, EFI, Volume Osc.
- **Commits:** one for the batch (the kernels share helpers).

## Open
- **Price Oscillator (PPO):** I implemented TradingView's "Price Oscillator" as I remember it: Short Length 10, Long Length 21, Source, Exponential, one plot "PPO" = (short − long) / long × 100. If the intended script is the MACD-like Percentage Price Oscillator (12/26/9, Histogram, PPO, Signal), it needs another pass. Please compare to TradingView.
- **BBW** includes TradingView's Highest Expansion / Lowest Contraction lines (length 125 each) from memory.
- **Flat or zero cases return `null`:** Stoch RSI and %B on a flat window, UO/CMO on zero range or movement, BoP with no range, ROC from 0. Not hit by the fixtures.
- **A/D, PVT and OBV are running totals** with warm-up 0, so they differ from TradingView by a constant when the chart has more history than the read; Chaikin Oscillator is immune (the constant cancels).
- **Parity is against PineTS,** not captured TradingView values (P4-7).
- **Web:** new panes, levels and the histogram AO were not checked in the browser.
