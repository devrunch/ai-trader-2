## Deviations from the brief, and why

- The three required unit suites were written and observed red before implementation. The binary WebSocket/container integration suite was added after the initial adapter implementation; it was not observed red first. This does not meet the brief's full tests-first sequencing requirement.
- Added a small SDK runtime helper because KiteTicker 5.3.0 stores its socket, event listeners and timers in module-level globals. Ordinary multiple instances cannot satisfy independent connections; isolation retains the required KiteTicker implementation and disables its auto-reconnect. The feed constructor keeps the mapping, allocation, session and breaker closures together so replacement transports share that state.
- Added UNSUPPORTED to the shared contract and updated its web consumer test because the required cap error was absent from ERROR_CODES. No rule configuration was changed.
- Extended candle-store conflict detection for repair-flag-only updates so newly backfilled outage minutes are marked repaired even when OHLCV is unchanged.
- Extended the existing nightly job to retry failed outage windows for subscribed instruments outside the held/popular list, rather than only logging a deferred retry.
- An auth rejection explicitly invokes the existing session `refresh()` before `getAccessToken()` once per retry cycle. Calling only the getter would reuse a still-locally-valid but upstream-rejected token.
- The smoke accepts configuration JSON on stdin so it does not read environment files or access process.env outside main.ts.
- No LikeC4 model changes were made; the manager owns that model.
