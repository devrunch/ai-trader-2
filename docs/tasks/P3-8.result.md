# P3-8 Result: email alerts

Owner request: "automate and notify using mail" (other SMTP; credentials to be added later).

## What changed
- **`shared/notify`:** a `Notifier` with an SMTP adapter (nodemailer 10.2.1, pinned 18 days old) and a disabled stand-in.
  - Sending never throws, and has a 20 s timeout.
  - `AlertGate` (Redis `SET NX PX`) allows one alert per key per window, across processes.
  - The config adds `SMTP_URL`, `ALERT_EMAIL_FROM`, `ALERT_EMAIL_TO` (comma list) and `APP_URL`; mail stays disabled until all are set.
- **Market-data:**
  - `sessionCoverage` (domain): head and interior gaps, plus where the data ends.
  - `CheckSessionCoverage`: repairs up to 5 gaps per instrument through `FillHistory`, then re-measures.
  - `CandleStore.instrumentsWith1m`.
  - Public `isTradingDay` and `isMarketOpen`.
- **The `alerts` module (jobs, IST):**
  - `zerodha-reminder` (08:45, trading days only): if Kite isn't connected, email the `/admin?tab=zerodha` link, once a day.
  - `data-report` (15:50): checked and repaired counts, calendar drift (data ending before the calendar close, grouped), and remaining gaps.
  - `ops-watch` (every 5 min): a failed job, or a feed stale, reconnecting or stopped for 5 minutes or more while its market is open; each at most hourly.
- **Admin:** an Alerts tab shows the mail status, masked recipients and a "Send test email" button (`GET /api/v1/admin/alerts`, `POST /api/v1/admin/alerts/test`).

## Tests
`notifier` (6), `session-coverage` (5, sabotage-checked), `check-session-coverage` (3), `data-report` (2), `alert-jobs` (7), the `instrumentsWith1m` integration test, the real `AppModule` boot, and the web alerts tab (1).

## Owner action
Add `SMTP_URL`, `ALERT_EMAIL_FROM` and `ALERT_EMAIL_TO` to `apps/api/.env` (see `.env.example`), restart the API, then use Admin → Alerts → Send test email.
