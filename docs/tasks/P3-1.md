## Rules
- **The sequence:** `INCR md:seq:<instrumentId>` gives `seq` (starting at 1). It isn't reset on restart, and no `seq` is ever reused.
- **Publish:** `PUBLISH md:bars:<instrumentId> <JSON BarUpdate>`. The `INCR` and `PUBLISH` run atomically in one Lua script, so two processes can never interleave a `seq` and its message.
- **Also keep** the last 300 updates per instrument in a capped Redis list (`LPUSH` plus `LTRIM` in the same script), so a briefly disconnected API instance can replay `seq > n` without a database read. Add `ReadSeq.replay(id, afterSeq): BarUpdate[]` (empty when `afterSeq` is older than the list keeps, meaning the caller must resync from `/bars`).
- **A Redis failure while publishing** is logged at `warn` and doesn't affect persistence. A missing publish is detected by clients as a seq gap.
- **`GET /api/v1/bars/seq`:** the current `md:seq:<id>` (0 if absent). Same validation and rate-limit guard as `/bars`.
