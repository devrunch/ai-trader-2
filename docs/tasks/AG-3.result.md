# AG-3 execution venue, auto-trade and trade journal

- Venue: `ExecutionVenue` port with `PaperVenue` (today's paper use cases) and a `BrokerVenue` stub whose every call refuses (no Kite session, token or order call anywhere). `VenueRouter` picks broker only when `EXECUTION_MODE=broker` AND `NODE_ENV!=production` AND the user opted in (`execution_prefs`, default off; `GET/PUT /v1/agent/execution`, PUT refused unless allowed). Production with `EXECUTION_MODE=broker` fails config load and router construction. The existing "agent cannot reach a broker" source-scan test still passes unchanged.
- Auto-trade: `autoTrade {enabled, maxRiskPct, maxTradesPerDay, requireBacktest}` on a task (`POST /v1/agent/tasks/:id/auto-trade`, assistant tasks only). In a background wake-up `placePaperOrder` places an entry only with auto-trade on and inside its limits, after the existing risk gate (stop required, reward:risk, loss limits, window); otherwise it proposes a new `place-order` action card that places on the user's confirm (risk gate runs again). Chat entries behave as before. A backtest counts when `runBacktest` ran in the same wake-up.
- Journal: `agent_trades` (migration `0028_agent_trades`, also `tasks.auto_trade`, `execution_prefs`) written on every agent entry (trigger, skill, rationale, entry/stop/target, risk, backtest); `GET /v1/agent/trades` adds status and P&L from the paper engine. Web: "Trade journal" tab in the Trading panel, auto-trade switch (labelled PAPER) on tasks, order card.
- Tests: `domain/venue.spec.ts`, `execution-venue.spec.ts`, `power-tools.spec.ts` (limits, cap, journal, propose-vs-place), `action-pine.spec.ts` (card confirm), `trade-log.spec.ts`, `agent-tasks.spec.ts`, config, web specs. Gate passes. No Docker int-spec for the new stores.
- Judgment calls: P&L is realised exits of that trade's orders plus the open position's unrealised P&L (approximate if two trades share an instrument); the card deps method is `submitOrder` because the broker-scan test forbids the word `placeOrder` in agent code; `CLAUDE.md`'s "no code path reaches a broker" still holds: the stub holds no broker access.
