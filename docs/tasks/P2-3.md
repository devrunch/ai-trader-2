# Task P2-3: Candle store

Read `AGENTS.md` first. It's binding. Do only what this brief asks. Plan: `docs/superpowers/plans/2026-11-08-phase-2-market-data.md` § P2-3.

## Goal
Persist 1-minute bars (monthly partitions) and daily bars in Postgres. Read them by cursor (`before` and `since`) at any interval, aggregating on read through the P2-1 grid. Hold the forming bar per instrument in Redis. Writes are idempotent and repairs visible.

## Tables
- **`bars_1m`:** partitioned by range on `ts`, one partition per month (`bars_1m_YYYYMM`). Columns: `instrument_id text not null`, `ts timestamptz not null`, `open/high/low/close double precision not null`, `volume double precision null`, `source text not null`, `repaired boolean not null default false`, `updated_at timestamptz not null default now()`. Primary key `(instrument_id, ts)`, declared on the parent.
- **`bars_1d`:** `instrument_id`, `session_date date`, OHLC, `volume` null, `adj_factor double precision not null default 1`, `source`, `repaired`. Primary key `(instrument_id, session_date)`. Not partitioned.
- **Partitions** for the current month plus the next 2 are created at boot and by a monthly job (`bars-partitions`: cron `0 1 1 * *` IST). Writing to a month with no partition creates it first; never fail a write because a partition is missing.

## Interfaces you produce (exact)
```ts
export interface CandleStore {
  upsert1m(instrumentId: string, bars: readonly Bar[], source: string): Promise<{ written: number; repaired: number }>; // batch ≤ 1000; ON CONFLICT updates only when values differ, setting repaired=true then
  upsert1d(instrumentId: string, bars: readonly Bar[], source: string): Promise<{ written: number; repaired: number }>;
  range1m(instrumentId: string, from: number, to: number): Promise<Bar[]>;       // [from, to), sorted asc
  range1d(instrumentId: string, from: string, to: string): Promise<Bar[]>;
  earliest(instrumentId: string, daily: boolean): Promise<number | null>;
}
export interface FormingBarStore {                       // Redis hash `bar:forming:<id>` → JSON {bar, cumVolume, seq}
  get(instrumentId: string): Promise<{ bar: Bar; lastCumVolume: number | null; seq: number | null } | null>;
  set(instrumentId: string, v: { bar: Bar; lastCumVolume: number | null; seq: number | null }): Promise<void>; // TTL 2 days
  clear(instrumentId: string): Promise<void>;
}
export type BarsCursor = { before: number } | { since: number } | { latest: true };
export interface BarsPage { bars: Bar[]; nextBefore: number | null; complete: boolean } // complete=false when the store lacks older data (P2-4 read-through fills it)
export class ReadBars { execute(instrumentId: string, interval: Interval, cursor: BarsCursor, limit: number): Promise<BarsPage> }
```

## ReadBars rules
- **`limit`:** 1–5,000. `latest` returns the last `limit` bars; `before` returns `limit` bars strictly before it; `since` returns all bars with `time >= since`, up to `limit`.
- **Intraday intervals:** read 1-minute bars over a window big enough for `limit` buckets (estimate from the session length, then loop back if short), and `aggregate` with the instrument's calendar (`calendarFor(exchange)`).
- **`1D`:** from `bars_1d`. **`1W` and `1M`:** aggregated from `bars_1d`.
- **The forming bar:** with `latest` or `since`, the Redis forming bar is merged in as the newest bar when it belongs after the last stored bar (it's never persisted here).
- **`nextBefore`** is the time of the oldest returned bar, or null when nothing is returned. `complete` is `false` when fewer than `limit` bars came back *and* `earliest()` is null or newer than the window asked for.

## Retention
Job `bars-retention`: daily 02:00 IST; drops `bars_1m` partitions older than 24 months (`DROP TABLE` the partition, not a row `DELETE`).
