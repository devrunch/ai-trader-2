## The patches (each one has a test in `pinets-patches.spec.ts`, run on the ESM and CJS builds)

1. **No 1 s forming-bar throttle.** `stream()` slept `1000 - elapsed` ms before recomputing a forming bar. Replaced by `0`. Test: three back-to-back ticks finish in under 700 ms (stock: about 3 s).
2. **Push provider, `interval: 0`.** With `interval: 0` the stream still slept `setTimeout(0)` (at least 1 ms) between ticks. Now `(n>0?setTimeout:setImmediate)(…)` in both sleeps, so a provider that answers when a tick arrives needs no timer. Test: with `setTimeout` faked, two ticks still compute.
3. **One point per bar time.** On a tick the stream rolled back its series but not plot output, so each tick appended a point. Before the rerun it now drops plot points at or after the first re-run bar's time. Test: four ticks on one bar plus a new bar leave exactly one point per bar time.
4. **Exchange prefix kept.** Three `includes(":")?split(":")[1]` sites (two in `request.security`, one in `security_lower_tf`) removed. Test: `request.security("NSE:Y")` and `("BSE:Y")` reach the provider with their prefix and give different data; `syminfo.tickerid` is the canonical id.

All four tests fail on the unpatched build (checked against the unpatched copy in the pnpm store: 8 of 8 fail). For patches 2 and 3 I also reverted just that patch in a copy: only its own test fails.

## Judgment calls

- **`pnpm patch` instead of the `patch-package` package.** pnpm hard-links `node_modules` files from its global store, so `patch-package` rewriting them in place would patch every project on the machine and survive a lockfile change. `patchedDependencies` makes the same unified diff and applies it at install, with the patch hash in the lockfile. The deploy build must copy `patches/` before `pnpm install` (I did not touch `deploy/**`, `scripts/**`).
- **Patch on the minified bundle**, because the package ships nothing else. The patch is anchored on code shapes, so a PineTS upgrade needs it redone (the tests will say).
- **Worker is a separate file** (`pine-worker.js` next to the module in `dist`); specs bundle it with esbuild into `node_modules/.cache/pine-worker/` because specs run TypeScript.
- **Unsupported-feature rule.** A static scan refuses `strategy()`, `strategy.*`, `library()`, `import`, and `request.financial/earnings/dividends/splits/economic/quandl/seed` up front. Anything else PineTS fails on is classified from its message: "x is not a function" and "Undeclared identifier x" name the feature and the first source line that uses it; transpile errors carry PineTS's own line. Other runtime errors become `PINE_ERROR` with no line. Alerts, drawings, `request.security_lower_tf` and the rest PineTS runs are allowed. The coverage table (P4-12) can narrow the list.
- **Only five input kinds** become definition inputs. Colour, time, symbol, timeframe, session, free-text `input.string` (no `options`) and `input.price` keep their script defaults and are not shown.
- **Plots:** only numeric plots are returned. `hline` is a level; shapes, `bgcolor`, labels, lines, boxes and tables are not in the result. Colour tokens cycle by plot order, not from the script's colours; width is 1.
- **`describe` runs the script on three synthetic bars** to find plots and levels; `request.security` there gets no data.
- **Failure codes.** A script problem or a timeout or out-of-memory is 422 (`PINE_ERROR`, `UNSUPPORTED`, `PINE_TIMEOUT`, `PINE_OUT_OF_MEMORY`) so the legend can show it; a worker that died under an instance is 503 `PINE_CRASHED`.
- **`request.security` data is cached in the worker for 5 s** per (symbol, timeframe, range), so a tick does not round-trip to the host for each secondary read. A higher-timeframe forming bar can therefore lag up to 5 s.
- **Secondary symbols** get the chart's time zone and an NSE/BSE session or 24x7 from their prefix.
- **`reason`** is added to the compute result only; live updates do not carry it.

## Open

- **A killed worker takes every live Pine instance on it down** (threads are shared). Sizes are small (2) and the live layer gets a 503 on the next tick; nothing reopens them automatically. `LiveIndicators` should re-open an instance whose push fails with `PINE_CRASHED`.
- **Describe and compute share the pool,** so a runaway `describe` also kills live instances on its worker.
- **No out-of-memory test** (a 256 MB allocation in CI is slow and flaky); the `ERR_WORKER_OUT_OF_MEMORY` branch maps to `PINE_OUT_OF_MEMORY` but is only reviewed, not run.
- **The web legend does not show `result.reason` yet,** and there is no UI to paste a script (P4-12 will call `/describe`).
- **Node version:** nothing here needs type-stripping; the compiled worker is plain JS.
- **Not checked in a browser.** Not run on the prod box (2 vCPU, 1.8 GB): idle cost is zero until the first script, then one worker of up to 256 MB.
- The wall-clock test `indicators.module.spec.ts` "ten built-ins within 5 ms" is flaky under load (noted by P4-9); I did not change it.
