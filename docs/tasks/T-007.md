# Task T-007: Logging and health

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal

## Interfaces
- **Consumes:** `APP_CONFIG` (T-005: `LOG_LEVEL`, `NODE_ENV`), `GlobalExceptionFilter` (T-006).
- **Produces:**
  - **`resolveRequestId(header: string | string[] | undefined): string`:** returns the incoming value if it's a single string matching `/^[A-Za-z0-9_-]{1,64}$/`, otherwise `crypto.randomUUID()`.
  - **`ObservabilityModule`** (global), built on `nestjs-pino` (exact latest) with pino (exact latest 10.x):
    - `genReqId` = `resolveRequestId(req.headers['x-request-id'])`;
    - the response header `x-request-id` is set on every response, including errors;
    - level from `APP_CONFIG.LOG_LEVEL`;
    - redact `req.headers.authorization`, `req.headers.cookie` and `res.headers["set-cookie"]`;
    - `pino-pretty` is not used anywhere: JSON only.
  - **`ReadinessRegistry`** (global provider):
    - `register(name: string, check: () => Promise<ReadinessResult>): void`, where `type ReadinessResult = { status: 'up' } | { status: 'down'; reason: string }`;
    - `runAll(timeoutMs?: number): Promise<{ ok: boolean; checks: Record<string, ReadinessResult> }>`;
    - each check runs in parallel, with a per-check timeout (default 2,000 ms); a timeout or throw counts as `down` with its reason (`'timeout'` or the error message, max 200 chars);
    - registering a duplicate name throws.
  - **`GET /health`** → `200 { status: 'ok' }`. Never runs readiness checks.
  - **`GET /ready`:**
    - `200 { status: 'ok', checks }` when every check is up (and when none are registered);
    - `503 { status: 'error', checks }` otherwise.

    This is the readiness response shape, not the error body, because load balancers read it.
  - **The filter** now logs via the pino logger with `requestId` taken from `request.id`.

## Tests to write first
- **`request-id.spec.ts`:**
  - `keeps a valid incoming request id` → `'abc-123_X'` gives the same;
  - `replaces an invalid or oversized request id` → `'a b'`, 65×`'a'`, `['x','y']` and `undefined` each give a UUID (`/^[0-9a-f-]{36}$/`).
- **`readiness.spec.ts`** (fake timers):
  - `ok with no checks` → `{ ok: true, checks: {} }`;
  - `reports a failing check with its reason` → a throw of `new Error('conn refused')` gives `{ status: 'down', reason: 'conn refused' }` and `ok: false`;
  - `times out a hanging check` → a never-resolving check with `runAll(100)` gives `reason: 'timeout'` after advancing 100 ms;
  - `rejects duplicate names`.
- **`health.controller.spec.ts`** (supertest on an app built with `AppModule.forRoot(testConfig)`):
  - `health returns ok without touching dependencies` → register a check that throws; `/health` is still 200;
  - `ready is 503 and names the failing check` → `checks.fake.status === 'down'`;
  - `ready is 200 when all checks are up`;
  - `response carries x-request-id` → sent `abc-123` comes back `abc-123`; when none is sent, a UUID header;
  - `error responses carry the same request id in header and body` → a 404 route gives the header equal to `body.requestId`.
