## Tests

- **Parity (FR-IN-2):** `infrastructure/native/native-runtime.parity.spec.ts` runs 31 input variants (every built-in, every MA type, smoothing, anchor and band mode) on 900 seeded 15-minute bars that cross a day, month, quarter and year boundary and a Monday, with one zero-volume bar. Each must equal its own Pine source on PineTS 0.13.1 to 1e-9 on every bar, `null` on exactly the same bars. All pass.
  - **Mutation check:** an EMA alpha change of 1e-7 relative, or a VWAP timezone change, makes 9 of the 31 cases fail.
- **Incremental (FR-IN-6):**
  - Each built-in, after five ticks on a forming bar and then the next bar, equals a fresh full run exactly (`toEqual`, difference 0).
  - All ten built-ins on one forming-bar tick after 5,000 bars: p95 below 5 ms asserted; measured about 0.11 ms.
- **Service:** warm-up read size, `before`, 5,000 cap, offset, status pass-through, empty bars, NOT_FOUND, 422 naming the input, Pine UNSUPPORTED, resolver order, replace/add/out-of-order, offset streams, serialised pushes.
- **Controller:** list, detail plus 404, compute contract, 422s, Pine through the same endpoint, 429.
- **Web:** indicator layer (panes, gaps, levels, partial repaint, removal), input draft, a legend/dialog flow over MSW (add, invalid input message, apply, remove, error text), and the live chart (refetches once per new bar, never per tick).

## Deviations from the brief, and why

- **No Pine runtime yet (P4-6).** `kind: 'pine'` is accepted by the same endpoint and returns 422 `{ reason: 'UNSUPPORTED' }`. The SRD requires a worker pool with 256 MB and 5 s limits (E26) and a source-level patch set (FR-IN-29). PineTS ships only a minified bundle, so "patch-package on the TypeScript source" needs the upstream repository at the 0.13.1 tag. Running user Pine in-process would let one script block the API event loop, so I did not ship that shortcut.
- **No indicator socket (P4-5).** It needs changes inside `modules/live` (`LiveSubscriptions`). The brief asked for minimal edits outside this module, so I left it out. Until it lands, the web refetches `compute` once per new bar: closed-bar values are exact, but the forming bar's indicator value is not live.
- **TradingView reference fixtures (P4-7) not committed.** The benchmark's captured TradingView values are not in the repo ("they are TradingView's data"). Parity is proved against PineTS, which matched TradingView to about 1e-9 in the benchmark.
- **Settings dialog:** only the Inputs tab. Style and Visibility tabs (FR-IN-10/11) are not built. The legend shows values of the newest bar, not the crosshair bar.
- **I wrote the plan file under `docs/superpowers/`** because the brief asked for it, although AGENTS.md reserves that folder for the manager.

## Follow-ups

- **P4-5:** `subscribeIndicators` on the live gateway, driven by `IndicatorService.open` streams.
  - One shared instance per (instrument, interval, ref, inputs hash).
  - Emit the bar's `seq`; re-seed on resync.
  - The web then feeds `LiveStore` and stops refetching per bar.
- **P4-6:** PineTS worker pool (E26), FR-IN-29 patches, `request.security` through `MarketDataService` (FR-IN-3, E27).
  - `PineRuntime` implements the existing port.
  - `RuntimeResolver([native, pine])` needs no other change.
- **Stochastic on a flat window:** a zero high-low range gives `null` for raw %K. TradingView's exact behaviour is not verified, because the random fixtures never hit it.
- **Gated warm-up kernels:** a later `na` input (for example from indicator-on-indicator, FR-IN-13) is skipped, not propagated as Pine would within a window. P4-9 must decide this.
- **Null volume:** it counts as 0 in VWAP and VWMA, so instruments without volume show no VWAP.
- **Long VWAP anchors:** warm-up is one anchor period, capped at 5,000 bars. A Month or Year anchor on 1-minute bars can still start mid-period.
- **Panes:** I could not check visually that Lightweight Charts drops an emptied indicator pane after removal. Needs a check in the browser.
- **Rate limit:** `POST /indicators/compute` has no session guard, the same as `/bars`. The manager may want a session guard before Pine (CPU-heavy) lands.
- **Design notes for the architecture README:**
  - The indicators module owns the catalog and runtimes.
  - Flow: `IndicatorService.open` reads bars → seeds an instance → returns a result and a stream.
  - The stream's add/replace/reject rule.
  - Panes: price pane 0, volume pane 1, indicators from pane 2.
