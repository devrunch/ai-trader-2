# Task P2-10d: Admin panel (operations)

Read `AGENTS.md` first. It's binding. Do only what this brief asks. **Make no real vendor calls**: tests use fakes and MSW.

## Goal
An admin-only `/admin` area where the owner runs the system day to day:
- **Zerodha:** connect, or paste a token; see whether auto-login is blocked and why.
- **Feeds:** each vendor's live state.
- **Jobs:** last run and outcome; run now.
- **Instruments:** source status; refresh now.

It looks like the terminal: the same tokens, dense and calm.

## SRD
FR-AC-2 (admin: provider health, job health), FR-UI-6/7 (loading and error states say why), FR-UI-8.

## Interfaces you consume (merged)
- Auth (P2-10b): `SessionGuard`, `RolesGuard`, `Roles`, `CsrfHeaderGuard` from `modules/auth/api/index.ts` (the only auth api import allowed), plus `AuthModule` in your module's imports; `CsrfHeaderGuard` on every POST, `useSession`, `RequireRole`.
- Zerodha (P2-10c): `GET /api/v1/admin/zerodha`, `POST …/token`, `…/auto-login`, `…/disconnect`. **There is no API callback:** the session cookie is `SameSite=Strict`, so it isn't sent on the cross-site redirect from Zerodha. A mismatched Zerodha account gets 400 with `reason: 'ACCOUNT_MISMATCH'`.
- Feed state: `RedisFeedStateStore` (`md:feed-state:<vendor>`); the leader: `md:leader`; subscriptions: `md:subs`.
- Jobs: `JobScheduler.lastRun(name)`, `runNow(name)`; job names `kite-session-refresh`, `instruments-refresh`, `bars-backfill`, `bars-partitions`, `bars-retention`, `held-continuous-roll`.
- Instruments: `instrument_source_status` rows; `RefreshInstruments` (locked, P2-10a).

## API (new admin-ops module, all admin-only; the CSRF header is required on POSTs)
- `GET /api/v1/admin/ops/feeds` → `{ leader: { instanceId, ttlMs } | null, vendors: [{ vendor, state, reason?, detail?, at? }], subscriptions: [{ instrumentId, count }] }`
- `GET /api/v1/admin/ops/jobs` → `[{ name, cron, tz, lastRun: { at, outcome } | null, next: iso | null }]`
- `POST /api/v1/admin/ops/jobs/:name/run` → 202. Unknown name → 404.
- `GET /api/v1/admin/ops/instruments` → `[{ source, status, reason?, count, lastSuccessAt }]` plus `total`.
- `POST /api/v1/admin/ops/instruments/refresh` → 202 (it runs through the job, so the lock applies).
- Contracts for all of these go in `@aitrader/contracts` (strict).

## Web (`apps/web/src/features/admin/…`)
- **Routes:** `/admin` (overview) with tabs Zerodha, Feeds, Jobs, Instruments, wrapped in `RequireRole role="admin"`. `/admin/zerodha/callback` is a web page (inside `RequireRole`). It reads `request_token` and `status` from the URL, removes them from the address bar at once (`history.replaceState`), and POSTs `/api/v1/admin/zerodha/token` (a same-site fetch, so the cookie is sent). It then navigates to `/admin` with a toast: connected, or the reason (`ACCOUNT_MISMATCH`, `INVALID_REQUEST_TOKEN`, or `status` not `success`). The token is never stored or logged in the browser.
- **Zerodha card:**
  - Status: connected until HH:MM IST, or not connected.
  - Auto-login: enabled or disabled, attempts today against the cap, blocked until … (CAPTCHA_REQUIRED).
  - Buttons:
    - **Connect Zerodha** opens `loginUrl` in the same tab;
    - **Paste request token** opens a dialog with one input and a Submit button;
    - **Try auto-login** is disabled while blocked, with a tooltip saying why;
    - **Disconnect** asks for confirmation.
  - If `redirectUrl` isn't set, show a one-line hint: "Set your Kite app redirect URL to `http://localhost:5173/admin/zerodha/callback`, or paste the request_token instead."
- **Feeds:** a vendor table (a state badge coloured with tokens: live = `--up`, stale = `--down`, reconnecting = `--warning`), the leader instance, the subscription list. Auto-refresh every 5 s while visible (TanStack Query `refetchInterval`, paused when the tab is hidden).
- **Jobs:** a table of name, last run (relative time), outcome badge, next run, and a **Run now** button with a pending state.
- **Instruments:** per-source status, count, last success, a **Refresh now** button.
- **Every view** has a skeleton, empty and error states with retry (AGENTS §4). ≤ 250 lines per `.tsx`; logic in hooks.
