# AG-4 backtesting for the user and the agent

- Contracts `backtest.ts` hold the condition DSL, spec, result and strategy shapes the page, API and assistant share. New `strategies` module: `BacktestRunner` (bars + server-computed indicator series + Lambda; the assistant's `runBacktest` now uses it), `Strategies` (save per user, cap 50, run), `/v1/strategies` (CRUD, `POST /run`, rate limited). Migrations `0029_strategies`, `0030_agent_trade_skips`.
- Variants (FR-BT-2): a run of a saved strategy records a fingerprint of all its parameters atomically (one SQL statement); repeats do not count, a failed run does not count; the page shows "N variants tried" with the overfitting note.
- Web `/strategies`: form builder with exact spec round-trip (nested logic falls back to read-only JSON), metrics, in/out-of-sample, equity curve, trade list, nav link. Trade journal shows skipped trades.
- Agent: `saveStrategy` tool. With `requireBacktest` the entry needs a `runBacktest` of that instrument in the same wake-up; profit factor < 1.1 or fewer than 20 trades means no trade and a "skipped" journal row with the reason (no profit factor, i.e. no losing trade, passes; skipped rows do not count toward the daily trade cap).
- Tests: strategies/backtest-runner/fingerprint/gate/tool specs and web specs. Gate (lint, typecheck, test, depcruise, knip, jscpd, build) passes.
