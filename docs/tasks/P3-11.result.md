# P3-11 Result: always-on instruments survive a slow start

**Live finding (2026-11-10, forex test):** the market-data process logged "Popular instruments unavailable; continuing without held subscriptions" when Redis timed out at start. From then on, popular instruments were recorded only while a browser watched them, until the next restart.

**Fix:** `FeedSupervisor.loadHeld` retries a failed load with backoff (5 s, doubling to 60 s), then subscribes the held instruments, including continuous contracts. `stop()` cancels a pending retry.

**Tests:** `retries the held list when it fails at start, then subscribes it` (RED, then GREEN) and `stops retrying the held list once stopped`. All 16 supervisor and process tests pass.

## Added: an expired Zerodha session reports AUTH_EXPIRED (live finding 2026-11-10)
- **Bug:** `KiteTickerClient.connect` rewrapped every error as `Error('PROVIDER_DOWN')`. The session's `NOT_CONNECTED` / `CAPTCHA_REQUIRED` lost its type, so the feed showed "provider down" for an expired token. The circuit breaker also counted it as a Kite failure and opened.
- **Fix:** session errors pass through unchanged (`isSessionError`), and the breaker ignores them. `ResilientFeed` already maps them to `stale: AUTH_EXPIRED` with the reason as detail, retrying with backoff up to 30 s (no Kite call is made while auto-login is off).
- **Tests:** `kite-ticker.client.spec.ts` (2): RED (`Error: PROVIDER_DOWN`), then GREEN.
