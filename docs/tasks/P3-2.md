## Goal
Browsers get one authenticated socket. Over it they subscribe to `{ symbol, interval }`:
- first a snapshot of recent bars with the current `seq`;
- then numbered bar updates in the requested interval, and feed status changes.

Subscriptions survive an API instance crash. A dead instance's interest expires; it never leaks a vendor subscription forever.

## Required changes

### 1. `ReadSeq.replay` returns `BarUpdate[] | null`
`null` means "too old, resync from `/bars`"; `[]` means "up to date". Today both cases return `[]`, which is ambiguous. Update the P3-1 tests.

### 2. Lease-based subscriptions (replaces the counter hash; protects against crashes)
- `RequestSubscription.acquire(instanceId, instrumentId)` and `release(instanceId, instrumentId)`.
- `md:subs` becomes a ZSET with member `<instanceId>|<instrumentId>` and score = lease expiry (epoch ms, now + 60 s). Each API instance refreshes its members every 20 s.
- The market-data reader (`subscription-requests.ts`):
  - wants an instrument while any non-expired member exists;
  - removes expired members (`ZREMRANGEBYSCORE`) on every read and on a 20 s timer;
  - still reacts immediately to `md:subs:changed`.
- **Inside one API instance:** keep a local reference count per instrument. Call `acquire` only on 0 → 1 and `release` only on 1 → 0. On graceful shutdown, release everything.
- Tests:
  - `a crashed instance's interest expires after the lease`;
  - `two tabs on one instance acquire once and release once`;
  - `two instances keep the instrument while either holds it`.

### 3. Gateway (`modules/live/`: api, application and infrastructure layers per R-rules)
- **Server:** Socket.IO 4.8 (latest 4.x) on the Nest HTTP server, path `/api/socket.io`, websocket transport first with polling fallback allowed.
- **Auth at the handshake:** read the cookie and call `CurrentUser`. No valid session → `connect_error` with `{ code: 'UNAUTHORIZED' }`. Re-check the session every 5 min. When it has expired, emit `session_expired` and disconnect.
- **Client to server** (acks, all validated with Zod strict schemas from `@aitrader/contracts` in `live.ts`):
  - `subscribe { symbol, interval, afterSeq? }` → ack `{ ok: true, subscriptionId } | { ok: false, code, message }`;
  - `unsubscribe { subscriptionId }`.
- **Server to client:**
  - `snapshot { subscriptionId, instrumentId, interval, bars, seq, status }`;
  - `bar { subscriptionId, seq, kind, bar }`;
  - `status { subscriptionId, status }`;
  - `resync { subscriptionId, reason }`.
- **Snapshot order** (no window for loss):
  1. subscribe to the Redis channel, buffering;
  2. read `seq0 = ReadSeq.current`;
  3. read the last 300 bars in the interval through `MarketDataService`;
  4. emit `snapshot` with `seq0`;
  5. flush the buffered updates with `seq > seq0`, then go live.
- **With `afterSeq`** (a reconnect):
  - try `ReadSeq.replay(id, afterSeq)`; on success, emit those updates instead of a snapshot (re-aggregated to the interval);
  - on `null`, emit a full snapshot.
- **Interval aggregation:** updates are 1-minute. For any other interval, keep the 1-minute bars of the current bucket per (instrument, interval), seeded from the snapshot. On each update, recompute that bucket with `aggregate` on the session grid, and emit the bucket bar with the update's `seq`. Daily intervals use the same rule for today's forming day bar.
- **Gaps:**
  - the server checks each instrument's incoming `seq`; on a gap (`seq > last + 1`), emit `resync { reason: 'SEQ_GAP' }` for its subscriptions;
  - after a Redis subscriber reconnect, emit `resync { reason: 'UPSTREAM_RECONNECT' }`;
  - the client then subscribes again with `afterSeq`.
- **Status:** forward `md:feed-state` changes for the instrument's vendor as `status` (same `DataStatus` shape as `/bars`).
- **Limits:**
  - at most 50 subscriptions per socket and 10 sockets per user (both: an ack error, `code: 'LIMIT'`);
  - subscribe and unsubscribe rate-limited per socket to 20 per 10 s;
  - an unknown symbol → ack `{ ok: false, code: 'NOT_FOUND' }`.
- **Backpressure:** if a socket's buffered amount exceeds 1 MB, drop pending `bar` events for it and emit one `resync { reason: 'SLOW_CONSUMER' }`. Never buffer without bound.
- **One Redis subscriber connection per API instance.** Use pattern subscriptions or per-channel subscriptions ref-counted across sockets. Not one connection per socket.
