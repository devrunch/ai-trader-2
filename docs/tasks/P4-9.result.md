## Design of the source reference

- **A `source` input is a price source (a string, as saved today) or `{ from: <instanceId>, plot: <plotId> }`.** Saved inputs stay valid: the string form is unchanged and the new form is an object, so no migration.
- **Instances are named by the client's own id** (the web store's `key`). The target request carries `instanceId`, `label` and `others` (the other indicators on the chart as `{ instanceId, label?, indicator }`). The server follows refs through `others`; it computes only what the target reaches.
- **Where it lives:** `IndicatorSpec` (builtin) and `IndicatorResult.inputs` use the new `IndicatorChartInputsSchema`. `IndicatorInputValuesSchema` stays plain on purpose: the agent module parses and prints it, and refs are not something the assistant proposes.
- **Compute:** `application/source-chain.ts` resolves the chain (cycle, depth, missing parent, unknown plot, one ref per indicator). `SourcedInstance` wraps the child: per bar it updates the parent first, then feeds the parent's plot to the child as the bar's `external` value. The child kernels read it through the existing `sourceInput` / `priceOf` (new `external` source), so every built-in with a `source` input works without touching kernels.
- **Each stream owns a private copy of its ancestors.** A live child needs no cross-stream coordination, and parent-before-child ordering holds by construction. The cost is duplicated parent work, bounded by the depth cap (5, the target included).
- **Warm-up** of a chain is the sum of the links' warm-ups, so the parent has converged before the child starts.
- **Live** (`LiveIndicators`): the bar subscription keeps the map of its indicators; the child's `others` come from that map (a parent subscribed in an earlier call or later in the same call is found). The shared-instance key includes the chain and the child's id; a plain indicator's key is unchanged.

## Judgment calls

- **A `null` parent value skips the child for that bar** (the child reports `null`). This settles the earlier follow-up for gated kernels: for the leading warm-up gap it equals Pine's `na` propagation. A `null` in the middle of a parent's plot would also be skipped rather than propagated through the child's window.
- **The parent's raw plot is used, before its offset** (TradingView feeds the series value, not the shifted plot).
- **A child of an indicator on its own pane paints there; there is no override yet.** "By default" is honoured, but the Style tab (FR-IN-10) does not exist.
- **Dropdown excludes the indicator itself and anything that already uses it**, so the UI cannot create a cycle; the server still rejects one.
- **Chained web requests wait for the catalog** so error messages can use "RSI 14" rather than ids.
- **Pine:** a Pine spec keeps plain inputs; Pine as parent or child of a chain waits for the Pine runtime (P4-6).
