# Task T-009: Postgres and Redis infrastructure

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal
The API connects to Postgres 18 (Drizzle) and Redis 8 (ioredis) with timeouts, backoff reconnects and clean shutdown. Both report on `/ready`. The API boots and stays up when either is down, and recovers by itself. Integration tests prove that with real containers.

## Interfaces
- **Consumes:** `APP_CONFIG` (T-005), `ReadinessRegistry.register` (T-007), `backoffDelay` and `withTimeout` from `@aitrader/resilience` (T-008), `UnavailableError` (T-006).
- **Produces:**
  - **`DB` token:** `NodePgDatabase<typeof schema>` from `drizzle-orm/node-postgres` (exact latest 0.45.x), over a `pg.Pool`:
    - `max: DATABASE_POOL_MAX`, `connectionTimeoutMillis: 3000`, `idleTimeoutMillis: 30000`;
    - every query gets `statement_timeout = 5000` (set via the pool's `options: '-c statement_timeout=5000'`);
    - the pool's `error` event is logged, never crashes the process;
    - `onApplicationShutdown` ends the pool.
  - **`DatabaseModule`** (global): provides `DB` and registers readiness `database` = `select 1` inside `withTimeout(…, 1500)`, giving `{ status:'up' }` or `{ status:'down', reason }`.
  - **`REDIS` token:** an ioredis (exact latest 6.x) client with `lazyConnect: true`, `maxRetriesPerRequest: 1`, `enableOfflineQueue: false`, `connectTimeout: 3000`, and `retryStrategy: (n) => backoffDelay(n, { baseMs: 200, maxMs: 10_000 })`. It never stops retrying. Connect on module init without awaiting success: boot must not depend on Redis. `error` events are logged at `warn`, rate-limited to one log per 10 s. `onApplicationShutdown` quits.
  - **`RedisModule`** (global): provides `REDIS` and registers readiness `redis` = `PING` inside `withTimeout(…, 1000)`.
  - **Test helpers** in `test/support/containers.ts`:
    - `startPostgres(): Promise<{ url: string; stop(): Promise<void> }>`;
    - `startRedis(): Promise<{ url: string; stop(): Promise<void> }>`;
    - `withToxiproxy(target)`, which returns `{ url, cut(): Promise<void>, restore(): Promise<void>, stop() }`. Use `@testcontainers/postgresql`, `@testcontainers/redis` and `@testcontainers/toxiproxy` (exact latest); the proxy lets a test drop and restore a dependency while its address stays the same.
  - **Migrations:** `pnpm --filter @aitrader/api db:generate` (drizzle-kit generate) and `db:migrate` (drizzle-kit migrate). The schema is empty for now.

## Tests to write first (`apps/api/test/infra.int-spec.ts`, real containers, 60 s hook timeout)
- `ready is ok when postgres and redis are up` → `/ready` 200, with `checks.database.status === 'up'` and `checks.redis.status === 'up'`.
- `ready reports redis down and recovers` → `cut()` the Redis proxy:
  - within 3 s, `/ready` is 503 with `checks.redis.status === 'down'`, while `checks.database` is still `up` and `/health` is 200;
  - after `restore()`, poll until `/ready` is 200 within 15 s.
- `ready reports postgres down and recovers` → the same shape for `database`.
- `app boots while redis is down` → start the app with `REDIS_URL` pointing at a cut proxy; `/health` is 200 and `/ready` is 503 naming `redis`.
- `app boots while postgres is down` → the same for `DATABASE_URL`.
- `a query error does not crash the process` → kill the proxy mid-query; the app still answers `/health` 200.
- `shuts down cleanly` → `app.close()` resolves within 5 s with the pool ended and Redis quit (no open handles: the test passes without `--forceExit`).
