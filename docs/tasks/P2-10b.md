# Task P2-10b: Minimal auth (username, roles, session cookie)

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal
Real login for the admin panel, built to grow into full user accounts (SRD FR-AC-1):
- users with a **username** and password; no email field for now (owner decision: admin accounts have no email);
- roles `admin` and `user`;
- sessions in httpOnly cookies;
- a guard and a decorator for role checks;
- a one-off CLI to create or reset the admin user, with the password typed by the owner at a hidden prompt.

## SRD
FR-AC-1 (sign-in, roles), NFR-SC-1 (no secrets in logs or responses), NFR-SC-5 (rate limits on auth).

## Rules
- **Users table:** `id uuid pk`, `username citext unique` (3–32 characters, `[a-z0-9_.-]`, lowercase), `password_hash text`, `role text` (`admin` or `user`), `created_at`, `disabled boolean default false`, `failed_logins int default 0`, `locked_until timestamptz null`.
- **Hashing:** argon2id (`@node-rs/argon2`, exact latest) with the library's recommended defaults. **Password policy:** ≥ 12 characters.
- **Sessions:**
  - an opaque random 32-byte ID, stored in Redis as `session:<id>` → `{ userId, role, createdAt }`, TTL 12 h sliding;
  - cookie `aitrader_session`: `HttpOnly`, `SameSite=Strict`, `Secure` in production, `Path=/`;
  - logout deletes the Redis key and clears the cookie.
- **Brute force:**
  - per-IP rate limit on `POST /api/v1/auth/login` (5 per minute, burst 5);
  - per-user lockout: 5 failed attempts → `locked_until = now + 15 min`;
  - the error is always a generic `UNAUTHORIZED` "Invalid username or password", the same for an unknown user and a wrong password, with similar timing (hash a dummy password when the user is unknown).
- **Endpoints:** `POST /api/v1/auth/login` (`{ username, password }`) → 200 `{ user: { id, username, role } }` plus the cookie; `POST /api/v1/auth/logout` → 204; `GET /api/v1/auth/me` → the user, or 401.
- **Guard:** `SessionGuard` loads the session (401 if absent or expired). `@Roles('admin')` plus `RolesGuard` → 403 for the wrong role.
- **CSRF:** `SameSite=Strict` plus a required header `X-Requested-With: aitrader` on state-changing requests; `apiFetch` sends it.
- **Web:**
  - `/login` page: username and password, error states, redirect back on success;
  - `useSession()`: TanStack Query on `/auth/me`;
  - `RequireRole role="admin"` wraps admin routes and redirects to `/login`.

## Tests to write first (names)
- **Domain and application:**
  - `rejects passwords shorter than 12`;
  - `normalises usernames to lowercase and validates characters`;
  - `login returns the same error for unknown user and wrong password`;
  - `locks the account after 5 failures for 15 minutes`;
  - `successful login resets failures`.
- **Controller:**
  - `sets an httpOnly SameSite=Strict cookie on login`;
  - `me returns 401 without a session`;
  - `logout clears the session`;
  - `admin route returns 403 for a user role`;
  - `state-changing requests require X-Requested-With`;
  - `login is rate limited per IP`.
- **Integration:**
  - `admin:create creates then resets an admin`, driving the use case directly, not the TTY;
  - `sessions expire after the TTL`.
- **Web:**
  - `login page submits and redirects`;
  - `RequireRole redirects anonymous users to /login`.
