# Task P1-5: Master persistence and daily refresh

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal
Store the instrument master and its provider mappings in Postgres, and refresh them daily from the P1-4 sources.
- **Isolation:** one source failing never touches another.
- **Atomicity:** a refresh applies per source, all or nothing.
- **Idempotence:** running twice changes nothing more.
- **Change history:** every change is recorded, so old IDs still resolve after renames, delistings and expiries.

## Refresh rules
1. **Per source, independently** (never in one shared transaction): fetch, then `loadSource`, then `diffMasters(prev, next, at, identity)`, then `applySource`.
   - Kite identity = the `exchange_token` part of `providerToken`, scoped by exchange as `<exchange>|<exchange_token>`.
   - Deriv and Nasdaq use no identity, so there are no renames.
2. **`applySource`:**
   - upsert every `next` instrument with `status: 'active'` and its mappings;
   - instruments in `prev` but not in `next` keep their row, with status set to `delisted` or `expired` per the change;
   - renamed instruments get `status: 'delisted'` and a `renamed` change pointing at the successor;
   - mappings of instruments no longer listed are deleted;
   - insert the changes;
   - all in one transaction, inserting in batches of ≤ 1,000 rows.
3. **A source that throws** (fetch or apply) leaves its rows untouched. It's recorded with `setSourceStatus(…, { status: 'stale', reason: <message ≤ 200 characters> })` and logged at `warn`. The other sources continue.
4. **After all sources:**
   - `purgeExpired(today - 30 days)`;
   - then `SearchIndex.rebuild(await listForIndex())`;
   - `today` is the `Asia/Kolkata` date from an injected clock.
5. **Idempotent:** refreshing twice with the same snapshots produces no new changes and the same rows.
6. **Jobs:**
   - `instruments-refresh`: cron `0 7 * * *`, `Asia/Kolkata`, `graceMs` 6 h, `maxRuntimeMs` 10 min;
   - on application bootstrap, if `instruments` is empty, call `JobScheduler.runNow('instruments-refresh')` (don't await it in boot).

## Resolve rules (`ResolveInstrument`)
Parse with `InstrumentId.parse` (invalid → `ValidationError`, 422), then:
1. **Continuous** (`parseContinuous`): resolve with `resolveContinuous` over `listContinuousCandidates(root, exchange)`, giving `{ instrument: <dated contract>, via: 'continuous', resolvedFrom: raw }`. When no contract is unexpired → `NotFoundError` with code `SYMBOL_NOT_FOUND`.
2. **Direct:** `findById`. An active or suspended instrument returns as is. A delisted or expired one returns with its status; don't hide it.
3. **Renamed:** when `findById` finds a delisted row that has a rename successor, follow `findRenameSuccessor` (max 5 hops, cycle-safe) and return `{ instrument: successor, via: 'renamed', resolvedFrom: raw }`.
4. **Unknown:** throw a `DomainError` with code `SYMBOL_NOT_FOUND` (404), details `{ id: raw, suggestions: SearchIndex.suggest(ticker, 5).map(String) }`. Add `SymbolNotFoundError` to `shared/errors/errors.ts` (404, `SYMBOL_NOT_FOUND`).
