# P4-B12: indicator chart bugs B1 and B2

## B1: Supertrend diagonals
**Root cause (web, not the kernel).** The Supertrend kernel is correct: a flip gives `…U D…`, with `up` and `down` never both set and `null` on the other plot (checked on a 120-bar series). Lightweight Charts 5.2.1 `walkLine` draws a line through consecutive *non-whitespace* items, so a `{ time }` point does not break the line; it is joined over. Any plot with a null in the middle (Supertrend, any gap) was drawn as one diagonal.

**Fix (one series per plot).** In lwc 5.2.1 `walkLine`, with `LineType.Simple` the segment ending at item i is stroked with the style of item i-1 (`lineTo` happens before `changeStyle`). So `bridged()` in `indicator-layer.ts` gives the last valued point before each null a per-point `color: 'transparent'` (`LinePoint` gained an optional `color`), and the bridge is invisible. The layer keeps each plot's points; a live point that moves where the nulls fall (a null arriving, a forming bar turning null or back to a value) repaints the plot with `setData`, because `update` cannot reach an older point. Any other live point is a plain `update`. Applies to line, step and area plots; histograms and circles are untouched (a transparent circle would vanish).

- **Area:** the fill polygon for the segment ending at i also uses the style of item i-1 (`finishStyledArea` with the same `currentStyle`), so `lwc-chart.ts` maps the point colour to `lineColor`, `topColor` and `bottomColor`; the fill bridge is hidden too. Not checked on a canvas, only by reading the renderer.
- **Step lines:** a known limitation. In the `WithSteps` branch the horizontal run is stroked with the previous point's style (hidden), but the vertical at the new point is stroked with the new point's style, so a short vertical stub remains at the start of each run. Making the first point after the gap transparent would hide it but also the first horizontal of that run. No built-in uses a step plot with nulls.

## B2: indicators on bars the chart does not show
**Root cause (found by reading; not reproduced on real data).** Server compute and the chart both read `MarketDataService.bars`, so a divergence needs the stored data to change between the two reads. `ReadBars.execute` treats a page as complete when it has `limit` bars, whether or not there is a hole inside it. The indicator request asks for `limit + warm-up` bars, can need an older fill from the vendor, and so can fill a hole that the chart's earlier 500-bar page was served without. The chart never refetched, so the indicator had bars (and values computed on them) that the chart lacked; the extra time points opened a gap in the candles and the Bollinger lines bridged it.

**Fix.** `ChartAdapter.missingTimes(times)` lists indicator times inside the chart's span that it has no bar for. `LiveChart` refetches the latest page and merges it (`mergeHistory`) when an indicator result has such times, once per missing set per symbol/interval.
