# P3-2 Result

Codex implemented increments A and B1–B6, then hit its usage limit just before the final `pnpm check`. The manager reviewed the work, fixed one bug and ran the full check.

## What changed
- **Market-data:**
  - `ReadSeq.replay` returns `null` when the requested seq is too old (resync from `/bars`), and `[]` when up to date.
  - Lease-based subscription interest: `RequestSubscription` keeps the reference counts (application layer); `RedisSubscriptionLeases` holds a ZSET with expiry scores, refreshes every 20 s and caught timer errors (infrastructure). `API_INSTANCE_ID` is added to the config.
- **The live module:** a Socket.IO 4.8 gateway at `/api/socket.io` with cookie auth and a 5-minute session re-check.
  - Subscribe and snapshot ordering: watch, then buffer, then `seq0`, then bars, then snapshot, then flush.
  - Interval aggregation on the session grid; `SEQ_GAP`, `UPSTREAM_RECONNECT` and `SLOW_CONSUMER` resyncs; `afterSeq` replay.
  - Status forwarding; limits (50 subscriptions per socket, 10 sockets per user, 20 calls per 10 s).
  - One shared Redis subscriber per instance.

## Manager fix
- **A resync left the subscription registered**, holding its watch, its lease and a slot toward the 50 limit, while the client resubscribed under a new ID. A resync now removes it.
  - Test `resync removes the subscription so repeated gaps never leak watches, leases or the limit`: RED (3 leaked watches), then GREEN.
