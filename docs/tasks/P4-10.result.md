# P4-10 result: indicator presets and templates (FR-IN-12, FR-IN-14)

Scoped to what a trader uses first. "My scripts" (FR-IN-19, FR-IN-28) is not built; it waits for the Pine runtime.

## Changed
- Migration `0023_indicator_library` (journal idx 20): `indicator_presets` (name NULL = the user's default; partial unique indexes), `indicator_templates` (unique per user and name, favourite flag, jsonb items).
- Contracts: `packages/contracts/src/indicator-library.ts`.
- API (`modules/indicators`): `IndicatorPresets` and `IndicatorTemplates` use cases, Drizzle stores, `IndicatorLibraryController`. Session guard on all routes, CSRF header on writes. Caps: 50 presets (defaults count), 30 templates, 10 indicators per template.
  - `GET /v1/indicators/presets`, `PUT /v1/indicators/presets/defaults/:indicatorId`, `POST /v1/indicators/presets`, `DELETE /v1/indicators/presets/:id`
  - `GET|POST /v1/indicators/templates`, `PATCH|DELETE /v1/indicators/templates/:id` (PATCH sets `favourite`)
- `IndicatorService.checkInputs` validates ids and bounds before anything is stored.
- Web: settings dialog footer (presets select, Save as default, Save preset as...), picker adds with the saved default, "Templates" dialog beside Indicators (save, apply, favourite, delete).

## Judgment calls
- The store keeps ids and inputs only, no style, so templates hold only those.
- Template items carry their own `key`; applying replaces the chart's set with fresh keys and remaps source refs. Presets drop source refs.
- Reusing a preset or template name is a 409, not an overwrite.
- The library controller is registered before `IndicatorsController` so `presets`/`templates` are not read as `:ref`.
- Reset settings returns to the user's default when one exists.

## Left open
- No rename of templates or presets, no delete of a saved default.
- Per-plot style is not stored by the web store yet.
