# P4-5 — Live indicators over the socket

**Model:** Sonnet. **Branch:** `task/P4-5-live-indicators`. **Plan:** `docs/superpowers/plans/2026-11-09-phase-4-indicators.md` (row P4-5). **Requirements:** FR-IN-5, FR-IN-30.

## Goal
Indicators on the chart update on every tick of the forming bar, from saved state, through the same socket as bars, instead of the web re-fetching `/indicators/compute` once per bar.

## Build
1. **Socket message `subscribeIndicators { subscriptionId, indicators[] }`** on the live gateway (`apps/api/src/modules/live/api/live.gateway.ts`).
   - `subscriptionId` names an existing bar subscription on the same socket. Each item is an `IndicatorSpec` plus a client `instanceId`.
   - Validate with Zod contracts in `packages/contracts/src/indicator.ts`.
   - Reply with the initial `IndicatorResult` per instance, computed by `IndicatorService.open` (it already returns a result and an `IndicatorStream`).
2. **Updates:** emit `indicator { instanceId, barTime, values, seq }` (the existing `IndicatorUpdateSchema`) for every bar update that subscription receives. `seq` is the bar's `seq`, so the client can order and drop stale frames.
3. **Sharing:** one server instance per (resolved instrument, interval, ref, inputs hash), ref-counted across sockets. The last unsubscribe or a disconnect closes the stream.
4. **Resync:** when the bar stream resyncs (gap or `afterSeq` miss), reset that subscription's indicators and send a fresh initial result.
5. **Web:**
   - `useChartIndicators` (`apps/web/src/features/indicators/use-chart-indicators.ts`) subscribes through the live client (`apps/web/src/shared/live/live-client.ts`) and applies updates to `IndicatorLayer` per frame, without React state per tick.
   - Keep the HTTP compute as the first paint when the socket is down, the same way bars do.

## Tests (write them first)
- Socket client with fake Redis:
  - subscribe gives the initial result, then updates carry the bar's `seq`;
  - two sockets with the same spec share one instance (one `open` call);
  - a disconnect releases its references;
  - a resync re-seeds.
- Bad specs (unknown id, input out of range) get a typed error frame, not a dropped socket.
- Web: updates reach the layer without a React re-render per tick (follow the existing `series-sync` tests).
