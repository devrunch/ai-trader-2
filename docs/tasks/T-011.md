# Task T-011: Live-value store

Read `AGENTS.md` first. It's binding. Do only what this brief asks.

## Goal
The primitive that keeps live ticks out of React state. A `LiveStore` holds the latest value per key and notifies at most once per animation frame. Charts subscribe imperatively; text reads through a hook that re-renders at most once per frame, however many ticks arrive.

## Interfaces (exact)
```ts
export interface FrameScheduler { schedule(callback: () => void): void }
export const rafScheduler: FrameScheduler;   // requestAnimationFrame; falls back to setTimeout(cb, 16) when rAF is missing
export function createManualScheduler(): FrameScheduler & { flush(): void; readonly pending: number };  // for tests

export class LiveStore<V> {
  constructor(scheduler?: FrameScheduler);                       // default rafScheduler
  set(key: string, value: V): void;                              // stores immediately; schedules one flush per frame
  get(key: string): V | undefined;                               // always the latest value, even before the flush
  delete(key: string): void;                                     // removes value; subscribers notified on next flush
  subscribe(key: string, listener: () => void): () => void;      // per-key; returns unsubscribe (idempotent)
  subscribeAll(listener: (changed: ReadonlySet<string>) => void): () => void;  // once per flush with keys changed in that frame
}

export function useLiveValue<V>(store: LiveStore<V>, key: string): V | undefined;  // useSyncExternalStore(subscribe(key), () => store.get(key))
```

## Behaviour rules
- **One flush per frame:** `set` and `delete` mark the key dirty; the first dirty mark in a frame calls `scheduler.schedule(flush)` once.
- **Flush order:** the flush takes the dirty set, clears it, notifies the per-key listeners of each dirty key, then calls each `subscribeAll` listener once with the set.
- **Safe re-entry:** a `set` called inside a listener schedules the next frame and never re-enters the current flush.
- **Listener changes during a flush:** listeners added during a flush don't fire for that flush. Listeners removed during a flush don't fire if they haven't fired yet.
- **A throwing listener** doesn't stop the others: catch it, report it via `queueMicrotask(() => { throw err })`, and continue.
- **Zero dependencies:** no allocation per `set` beyond the dirty-set insert, and no React import in `live-store.ts`.

## Tests to write first
**`live-store.spec.ts`** (manual scheduler):
- `coalesces a flood into one notification with the latest value` → 1,000 `set('NSE:X', i)`, then `pending === 1`; after one `flush()`, the listener has been called once and `get` is `999`.
- `notifies only subscribers of changed keys`.
- `get returns the latest value before the flush`.
- `unsubscribe during notification is safe` → listener A unsubscribes itself and B, B (not yet called) isn't called, and nothing throws.
- `subscribeAll receives the set of changed keys once per frame` → `set` a, b, a, then flush gives one call with `{a, b}`.
- `set inside a listener schedules the next frame` → after the flush, `pending === 1` and the listener didn't loop.
- `a throwing listener does not block others`.
- `delete notifies subscribers and get returns undefined`.

**`use-live-value.spec.tsx`** (manual scheduler, Testing Library):
- `useLiveValue re-renders once per frame, not per set` → a component with a render counter: after the initial render, 100 `set`s plus one flush inside `act` give exactly 1 extra render, showing the last value.
- `useLiveValue switches keys cleanly` → rerender with another key shows that key's value and stops reacting to the old one.
