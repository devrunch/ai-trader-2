# Task P2-10c: Connect Zerodha (official login) and CAPTCHA handling

Read `AGENTS.md` first. It's binding. Do only what this brief asks. **Make no real Zerodha calls**: tests use fakes.

## Goal
Get the daily Kite token without depending on the scripted login:
- **Official login:** Kite Connect's redirect flow, started from the admin panel (built in P2-10d).
- **Manual fallback:** pasting a `request_token`.
- **CAPTCHA:** a CAPTCHA reply from the scripted login stops all automatic attempts at once, with a clear reason.
- **Auto-login:** allowed only where `KITE_AUTO_LOGIN=true` (the server with a static IP). Default `false`.

## Rules
- **CAPTCHA detection:** a `/api/login` response with `data.captcha` present, or `error_type === 'InputException'` and a message matching `/captcha/i`, throws `KiteLoginError('login', 'captcha required')` with the flag `captcha: true`.
- **CAPTCHA lock:** a CAPTCHA reply sets `vendor_sessions.auto_login_blocked_until = now + 24 h` and `auto_login_block_reason = 'CAPTCHA_REQUIRED'` (migration). While blocked, **no** scripted login is attempted, and `getAccessToken` throws `UnavailableError` with `details: { reason: 'CAPTCHA_REQUIRED', action: 'connect_zerodha' }`. A successful official connect clears the block.
- **`KITE_AUTO_LOGIN=false`:** `getAccessToken` never attempts a scripted login. With no valid token, it throws `UnavailableError` with `{ reason: 'NOT_CONNECTED', action: 'connect_zerodha' }`. The 06:20 job is registered only when auto-login is on.
- **Feed state:** these reasons make the Kite feed state `stale` with reason `AUTH_EXPIRED` and detail `CAPTCHA_REQUIRED` or `NOT_CONNECTED`, so the admin panel can show exactly what to do.
- **Endpoints**, all admin-only, with the CSRF header required on POSTs:
  - `GET /api/v1/admin/zerodha`:
    - `{ connected, expiresAt?, autoLogin: { enabled, blockedUntil?, reason?, attemptsToday, cap } }`;
    - `loginUrl: 'https://kite.zerodha.com/connect/login?v=3&api_key=<key>'`;
    - `redirectUrl` (the configured value or null).
  - `GET /api/v1/admin/zerodha/callback?request_token=…&status=success` exchanges the token through `generateSession`, stores it (expiry: the next 06:00 IST), clears any block, and redirects the browser to `/admin?zerodha=connected`. On a failure, it redirects to `/admin?zerodha=error&reason=…`. The `request_token` must match `^[A-Za-z0-9]{8,64}$`.
  - `POST /api/v1/admin/zerodha/token` with `{ requestToken }`: the manual paste. Same exchange; returns the status.
  - `POST /api/v1/admin/zerodha/auto-login`: try a scripted login now, respecting the caps and the block. Returns the status or a typed error.
  - `POST /api/v1/admin/zerodha/disconnect`: deletes the stored token.
- **Never** return or log the access token, API secret, password or TOTP. Log only stage and reason.
