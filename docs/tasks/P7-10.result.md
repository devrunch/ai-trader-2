# P7-10 assistant proposes shared Pine scripts

- New action kind `add-pine` (contracts) and tool `proposePineScript` (source or raw https link). `ActionCards.proposePine` runs the runtime's describe first; the card carries the definition (inputs/plots) or the error line, and a broken script can't be applied.
- Apply (user consent only) re-checks, saves via `PineScripts.create`, records `scriptId`; the web card then adds the script to the chart via `addPine`. Dismiss/expiry saves nothing. An edited copy from the client can't change the stored source/name.
- `pine-source.ts`: https only, no private/IP hosts, text/plain, 5 s, 200 KB (declared and streamed), redirects re-checked (max 3); the text only ever reaches the Pine runtime's sandbox. System prompt: one line. `PineScriptsModule` now exports `PineScripts` (+ `application/index.ts`).
- Tests: `action-pine.spec.ts`, `pine-source.spec.ts`, two cases in `chat.spec.tsx`. Gate (build:packages, lint, typecheck, test, depcruise, knip, jscpd, build) passes after one lint fix; no Docker specs.
- Judgment calls: the card name defaults to the script's own name; the name isn't editable on the card; a card applied twice never saves twice (idempotent), but a save followed by a lost card-state race could leave a saved script without an applied card.
